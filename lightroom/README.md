# Lightroom Classic 返图插件 0.1.29（Windows，第一版）

## 稳定性修复（0.1.29）

- 微信搜索填写的账号后按 Enter 进入聊天，识别聊天标题并在后续操作中检查标题是否变化。标题 OCR 支持原色、灰度和反色重试。搜索结果由客户端选择，应填写准确的微信号。
- 微信先连续操作发送本轮附件和留言，再统一核对聊天中的新增文件名、图片或 ZIP 卡片及草稿状态。核对失败保留“结果待核对”；通过后直接结束任务，不再次进入发送流程。客户端交接不代表上传完成或对方收到。
- QQ 留言聚焦编辑区、粘贴后按一次 Enter 发送；请在 QQ 中设置 Enter 发送。
- 后台每次启动默认暂停队列，人工点击继续或取消暂停后才开始发送。任务窗口支持多选批量继续，已完成任务跳过，不确定批次按人物核对。
- 人物目录保存归属标记。名称拼接碰撞或未知目录使用带短标识的新目录，避免覆盖另一人物或未知文件夹。同一已核实人物/账号仍按设置替换。
- 素材先复制到临时目录，目录替换和任务保存通过恢复记录协调；重启会恢复未提交的旧目录、清理已提交的备份。复制阶段不持有任务锁，界面忙时读取缓存。
- 修复保存失败后一直显示“正在发送”；任务窗口显示全部任务，不再截断为 50 条。
- 打包按 1 MB 分块检查取消；等待预打包也可终止，取消预打包后删除未完成 ZIP。

旧分享包 EXE 不包含本次修复，需要重新构建后分发。

## 提前准备下一任务的压缩包

当前人物素材准备完成、开始连接客户端时，后台单独准备下一项排队任务的 ZIP。仅对需要 ZIP 的微信任务预打包；QQ 和 1–8 张纯照片的微信任务无需打包。客户端仍逐个发送。正式发送前校验素材与 ZIP 指纹，符合时复用，变化时重新处理。预打包失败会在正式发送时重试。暂停后不启动新的预打包，正在打包的任务不能删除；打包完成不代表已发送。工具栏展示预打包状态。

## 按人物和账号保存素材

新任务将素材复制到导出位置下的“人物名称_实际发送账号”子文件夹。同名人物目录会清空，只保留本次素材；视频复制原文件。压缩包路径留空时，ZIP 保存到同一个人物文件夹；指定独立压缩包路径时，在该路径下建立同名人物子文件夹，并清空该目录旧内容。仍被未完成任务使用的目录禁止替换，请先取消旧任务。复制或创建任务失败会恢复旧目录。ZIP 仅包含当前任务的素材。Lightroom 临时导出批次目录保留，原素材不会移动。工具栏发送时保持显示并展示当前进度。更新后重新载入插件并重启后台。

## 自动连接

插件保持在本工程 `lightroom/PhotoReturn.lrplugin` 下安装时，会自动读取相邻工程的本机后台连接配置并核验服务身份，无须复制口令或确认配对。启用插件后 Lightroom 启动时初始化，后台启动后约 3 秒内连接；后台重启、插件重新载入后自动重连。真实插件响应才标记已连接，不将检测到进程当成连接成功。后台仍需运行，且 Lightroom 中插件需保持启用。若单独复制插件到其他目录导致相邻配置无法找到，仍可使用手动口令备用连接。

## 小型悬浮工具栏

启动后台后默认显示置顶悬浮工具栏，可拖动标题栏放在 Lightroom 顶部附近。包含绑定人物文件夹、绑定人物父文件夹、查看文件夹状态、发送当前文件夹、发送选中素材、连接设置与任务状态六个入口；另外可打开实时任务窗和复制口令。按钮通过已认证本机接口让 Lua 插件执行对应流程，不模拟鼠标菜单点击。首次仍需在 Lightroom 菜单中设置口令并重新载入 0.1.18 插件，连接后通常在 3 秒内响应。

同一时间仅执行一个工具栏操作。自动发送到 QQ / 微信期间工具栏隐藏，结束后恢复；任务窗可继续查看。点击工具栏关闭按钮会隐藏工具栏并打开任务窗，后台继续运行；任务窗上方可以再次显示工具栏。

## 压缩包位置和导出设置字体

导出设置窗口在导出位置下方新增“压缩包保存路径”，可填写或浏览选择；留空时 ZIP 保存到上面的导出根目录（JPEG 仍在其独立批次子目录内）。路径随任务保存，仅对新建任务生效；已有任务继续使用创建时的路径。只有需要打包的微信任务才生成 ZIP。设置窗口文字增大为 13，并提供滚动区域以避免底部选项超出窗口。

微信交付规则：同一任务 1–8 张照片直接选择原图片文件发送，9 张及以上（包含 9 张）打包 ZIP。含视频的任务保持打 ZIP。阈值按每个人物/接收账号任务分别计算，不是按整个选择范围计算。QQ 仍使用闪传。图片发送器仍需微信客户端实机验证，尤其是客户端可能出现图片确认或原图选项的情形。

## 菜单直接发送已选中素材

选中照片/视频，使用“文件 → 增效工具额外信息 → 返图：发送已选中素材（读取元数据账号）”。选择详细导出设置后，先核对人物、账号和数量，确认后由 Lightroom 导出选中照片为 JPEG，并自动加入发送队列，不再要求导出后的第二次确认。视频可选择包含，发送原视频。可跨文件夹、多人物混合发送。

此入口要求每张将发送的素材在元数据中填写 QQ 或微信号，缺少账号时提示并停止整批，不回退文件夹账号。人物名称空白时使用绑定人物名称或所在目录名。导出失败或取消导致数量不足时整批不发送。发送完成后沿用自动“已返图”状态同步。

## 手动和自动返图状态

元数据布局中新增“是否返图”，未设置显示“未返图”，可手动切换“已返图/未返图”。从此版本创建的发送任务会关联 Lightroom 目录文件和照片编号。任务成功提交客户端后，插件每 3 秒检查后台，将对应原照片标记为“已返图”；失败、不确定或尚在排队不标记。此标记不代表对方已接收。自动更新一次并记录确认，之后手动改回未返图不会因旧任务反复变为已返图。

使用时重启后台并重新载入插件。插件关闭或后台离线时暂停同步，恢复连接后补同步。此版本之前没有照片关联的任务不会自动补标，需手动设置。原照片从目录中移除、目录文件迁移或原片路径变化时，关联需重新核对。同步只修改目录文件中的插件字段，不改颜色标签或 RAW 图像内容。

## 在元数据中填写接收账号

重新载入插件后，在右侧“元数据”面板的字段布局下拉框（通常显示“默认值”或“自定”）中选择“摄影返图 · QQ / 微信”。可填写返图人物名称、QQ 号码、微信号/搜索名；发送渠道改为下拉选择“QQ”“微信”或“自动”。未选择时使用人物绑定默认渠道。这些字段属于每张照片；需要批量填写时先多选照片，并确认 Lightroom 将修改应用到选中的照片。

照片填写了账号时优先使用照片账号；两个账号都为空时沿用自身或父文件夹绑定。QQ 必须为纯数字。发送前仍确认人物、账号和数量。同一目录里不同账号或人物名称分成独立任务。字段保存在 Lightroom 目录文件中，不改 RAW 像素，也不表示任意外部软件能读取这些插件字段。

## 人物下有多个拍摄日期子文件夹

选中人物子文件夹中的一张照片，通过“返图：绑定人物父文件夹（子文件夹继承）”选择人物层级（如小渔）并填写账号。未单独绑定的子文件夹继承最近父层级的账号和人物名称，已单独绑定的子文件夹优先使用自身设置。发送入口仍只发送所选照片所在子文件夹，不包含兄弟或下级文件夹。

“返图：查看文件夹及子文件夹返图状态”按拍摄目录展示最近任务、数量和时间。常驻任务窗增加拍摄文件夹列。状态来自本插件后台任务记录；之前通过其他软件或手动发送的照片不能自动识别。最近任务已提交也不代表后来新增的照片已发送。继承按 Lightroom 目录文件隔离，迁移或重命名目录后需重新绑定。

按 Lightroom 人物文件夹管理，用户无需建立拍摄项目。照片先由 Lightroom 导出带调整效果的 JPEG，QQ 闪传直接发送，微信打 ZIP 发送。复用工作台发送模块。

## 安装

1. 在本工程目录运行 `启动Lightroom返图后台.bat`，自动打开常驻任务窗，每 0.8 秒刷新人物、接收账号、提交进度和任务状态。支持置顶、暂停后续任务、核对继续、取消任务和复制连接口令。最小化保持后台运行；关闭窗口会确认退出，正在发送时需要等当前任务结束。环境与摄影返图工作台一致，需 Python 和 `requirements.txt` 中的依赖。
2. Lightroom Classic 15.5.1：文件 → 增效工具管理器 → 添加，选择本目录中的 `PhotoReturn.lrplugin` 文件夹，启用插件。
3. 文件 → 增效工具额外信息 → “返图：连接设置与任务状态”，粘贴后台显示的连接口令。只连接 `127.0.0.1:17861`。
4. 在图库中选择人物文件夹内的照片，运行“返图：绑定选中照片所在人物文件夹”。填写人物名称、QQ 或微信；填写一个账号就用那个账号。两个都填时可选择渠道，自动默认 QQ。

## 发送选中素材（可跨人物文件夹）

选中照片 → 导出，在导出窗口的“导出到”选择“摄影返图 · QQ / 微信”。设置 JPEG 画质、尺寸、色彩空间和独立导出目录，点击导出。插件按照片原所在文件夹分组，缺少绑定时弹窗填写，导出全部成功后显示人物、账号和数量，确认后加入后台队列。取消确认会保留 JPEG，但不会发送。

## 发送整个人物文件夹

选中文件夹内任意一张照片 → 文件 → 增效工具额外信息 → “返图：发送当前人物文件夹全部素材”。使用目录文件中该目录的全部素材，不包含子目录、不包括尚未导入 Lightroom 的磁盘文件。弹出详细导出设置，可设置 JPEG 品质（1–100）、每张文件大小上限（MB/KB）、色彩空间、长边像素、不放大原图、分辨率和导出位置，并选择是否包含原视频。记住上次设置；每次在指定位置建立独立批次子文件夹，导出完再确认发送。默认原尺寸、90% 品质、sRGB、300 像素/英寸。需要水印、输出锐化等完整选项时使用 Lightroom 原生导出窗口入口。

## 状态和恢复

通过“返图：连接设置与任务状态”查看最近 50 个任务。结果待核对或失败会暂停后续队列；窗口可选择暂停任务继续或取消。对不确定批次，先检查客户端，再选择“已发送：跳过”或“未发送：重发”。取消任务不会撤回客户端中的附件。关闭后台后再启动，未完成任务暂停，需要明确继续，避免重复发送。

“已提交客户端”表示已交给 QQ / 微信操作，不代表上传完成或对方下载成功。完成后发送工作台现有自动留言。不能同时运行独立工作台的自动发送和插件后台自动发送；自动操作期间保持 QQ / 微信登录，避免操作鼠标键盘。

## 数据与限制

- 人物账号保存在 Lightroom 插件偏好中，以目录文件路径和原素材目录区分。同名文件夹不会串号。迁移/重命名目录或目录文件后需重新绑定。
- 本机口令、任务历史和微信 ZIP 保存在工程 `.lightroom-state/`，已排除 Git。后台内部复用工作台持久化结构，界面不要求建立项目。
- 导出的 JPEG 和发送的视频在发送完成前不能移动、覆盖或删除；后台会校验大小与修改时间。再次导出到新路径会生成新素材，第一版没有跨导出版本的替换功能。
- 状态窗口为手动刷新；第一版尚未在 Lightroom 照片上写入“已返图”自定义元数据。
- 视频不转成 JPEG。导出窗口中的视频采用 Lightroom 支持的导出结果；整文件夹入口直接发送原视频。
- 第一版完成 Lua 5.1 语法/模拟验证和后台测试，仍需在实际 Lightroom 15.5.1 中完成导出与真实联系人发送联调。

插件使用 Adobe 的 Lua SDK：[官方介绍](https://developer.adobe.com/lightroom-classic)。

文件大小限制使用 Lightroom 原生 LR_jpeg_useLimitSize / LR_jpeg_limitSize 参数，1 MB 按 1024 KB 换算。启用时禁用品质控件；限制的是每张 JPEG 的最大文件大小，实际可能更小，目标过小时 Lightroom 可报告导出失败，整批不提交发送。此限制不作用于视频或微信 ZIP。
